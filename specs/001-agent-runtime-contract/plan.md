# Implementation Plan: Agent Runtime Contract (ARC)

**Branch**: `001-agent-runtime-contract` | **Date**: 2026-05-13 | **Spec**: [spec.md](spec.md)
**Input**: Feature specification from `specs/001-agent-runtime-contract/spec.md`

## Summary

Define and implement the Agent Runtime Contract (ARC), a versioned specification of what the Kagenti platform provides to agent containers and what agents must expose in return. The contract is materialized as an AGENTS.md file (conforming to the AGENTS.md open standard) mounted at `/arc/AGENTS.md` in every managed agent Pod, alongside MCP server configuration at `/arc/mcp/servers.json` and skill artifacts at `/arc/skills/`. ARC features are configured via the AgentRuntime CR (`spec.arc`), and the controller generates target-specific contract content.

## Implementation Phases

### Phase A: Operator CRD + Webhook (kagenti-operator repo)

**Goal**: Extend AgentRuntime CRD with `spec.arc` fields and update webhook to inject ARC env vars and `/arc/` volume mounts.

1. Add `spec.arc` to AgentRuntime types (Go structs)
2. Regenerate CRD manifests and deepcopy
3. Update webhook Pod mutator to inject `ARC_*` env vars
4. Update webhook to mount `/arc/` volumes (ConfigMap-backed)
5. Add conditional `OTEL_EXPORTER_OTLP_ENDPOINT` injection based on `spec.arc.tracing.enabled`
6. Unit tests for new webhook mutation logic

### Phase B: Operator Controller (kagenti-operator repo)

**Goal**: Controller generates AGENTS.md and servers.json ConfigMaps per AgentRuntime CR.

1. Implement AGENTS.md template with YAML frontmatter generation
2. Implement MCP tool discovery via label selector (`kagenti.io/protocol=mcp`)
3. Implement servers.json generation in standard format
4. Create `<agent>-arc-contract` ConfigMap with ownerReference to AgentRuntime
5. Create `<agent>-arc-mcp` ConfigMap with ownerReference to AgentRuntime
6. Watch for MCPServerRegistration/MCP tool changes and regenerate ConfigMaps
7. Target-type detection: generate different AGENTS.md for Deployment vs Sandbox
8. Unit tests for ConfigMap generation and target-type logic

### Phase C: Backend + Helm (kagenti repo)

**Goal**: Update Python backend to include `spec.arc` in AgentRuntime manifests. Update Helm charts for ARC defaults.

1. Update `_build_agentruntime_manifest()` to include `spec.arc` fields
2. Add ARC configuration options to agent creation API
3. Update Helm `values.yaml` with ARC default values
4. Update agent namespace templates for any ARC-related namespace config
5. Integration tests on Kind cluster

### Phase D: ADR + Documentation (kagenti repo)

**Goal**: Write the ADR document (ODH-ADR-AgentOps-0004) and update existing docs.

1. Write ADR using prose plugin with reasoning voice
2. Update `docs/kagenti-agent-identity-architecture.md` to reference ARC
3. Update `docs/components.md` if applicable
